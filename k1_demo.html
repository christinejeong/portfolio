Overview

A live demo that serves SK Telecom's sovereign large language model, A.X K1, 519 billion parameters (MoE), on a single RebelServer™ with 8 RebelCard™ NPUs, and runs a real, working map-based AI agent on top of it.

The goal was to prove that "one domestic NPU server can run a frontier-scale model", not with benchmark tables, but with a living service: multiple users simultaneously ask everyday questions like "Where's a well-reviewed dermatologist in Mok-dong?", and the audience watches K1 reason, call tools, find real places, and pin them on a map in real time.

  • Agentic, not canned, the model plans, calls tools, and verifies results on its own.
  • Zero hallucinated venues, every place in an answer is verified against the live TMAP API before it can appear.
  • Every number on screen is measured, response times, token counts, NPU utilization. No fake data.

Why, and How

Why I built it. I was interning at Rebellions when the Rebellions × SK Telecom collaboration was announced. The claim, "a frontier-scale model runs on one domestic NPU server," existed as benchmark numbers. What it needed was something an audience could watch working. This demo turned the claim into a live service.

I chose a map agent on purpose: I wanted the demo to live inside everyone's daily life, not in a benchmark table. Finding a hospital or a pharmacy that is still open late on a weekend night is genuinely hard and time-consuming. This answers it in seconds, with real, verified places pinned on a map.

What it's made of. The backend is one dependency-free Python file: stdlib HTTP server and threads, streaming from K1 through vLLM's OpenAI-compatible API, grounding against the TMAP REST API, and reading NPU utilization from rbln-smi. The front end is vanilla HTML/CSS/JS with hand-rolled SVG for the live graphs. No frameworks, so it runs anywhere Python runs.

Where AI helped, honestly. I used Claude for UI scaffolding and refactoring passes on the server plumbing. The parts that make the demo trustworthy are the parts I designed and iterated myself: the agent-loop prompt rules, the TMAP grounding pipeline, the reliability guards, the 70-question bank, and the "every number is measured" principle, all tuned against live failures on real hardware.

System Architecture

A dependency-free Python server sits between the browser and the model: it orchestrates the agent loop, streams from K1 through an OpenAI-compatible API, grounds answers in TMAP data, and collects per-request metrics that the dashboard renders live.

The Agentic Tool-Calling Loop

The heart of the demo. Given a question, K1 emits tool calls as JSON, the server only parses, executes, and feeds results back. The model decides which tools to run and when it knows enough to answer. Round one always fans out in parallel, two K1 sub-inferences (Explore, Verify) plus a live TMAP search, so the dashboard's process graph shows genuine parallelism on real hardware.

animated to mirror the live dashboard: each stage lights up as the loop runs, and every step is recorded so any question's reasoning can be replayed

Reliability came from unglamorous engineering: a tool-name whitelist with variant normalization, duplicate-call detection that nudges the model to conclude, a one-retry format guard, a 6-round budget with a forced final answer, and a four-level graceful-degradation ladder that ends in a measured TMAP fallback, so the screen never shows a dead end.

Zero Hallucinated Venues

LLMs love inventing plausible place names. The demo makes that structurally impossible:

  • Pre-grounding, the question's area is geocoded and nearby real POIs are injected into the prompt, with rules against vague endings and irrelevant venues.
  • Answer verification, after generation, venue names are extracted from the answer and re-searched on TMAP; only places that exist (with coordinates) become map pins.
  • Strict chip matching, a venue chip renders only if every distinctive token of the verified name appears in the answer text.

Net effect: an unverified place cannot reach the screen. Zero hallucinated venues across hundreds of live queries.

Takeaways

  • Agent reliability is mostly prompt + parser engineering, whitelists, format guards, and duplicate detection mattered more than any single clever prompt.
  • Grounding beats guessing: making hallucination structurally impossible is a design decision, not a model property.
  • A demo is a product, "every number is measured" was the principle that made the audience trust the rest.
